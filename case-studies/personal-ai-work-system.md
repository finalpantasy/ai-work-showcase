# My personal AI brain

Working private knowledge system and operating rules. Public examples below are invented; source records and personal information remain private.

I work across marketing, software projects, research and team decisions. Starting a new AI conversation should not mean starting from zero. I built a private brain to keep useful knowledge within reach and a set of operating rules to make that knowledge useful in actual work.

It is more than a folder of prompts. It holds the background behind my work: what a project is trying to do, which decisions were made, what evidence supports a claim, what is still uncertain and how I want the work handled.

## The problem: forgetting what we already know

An AI assistant can give a confident answer while missing the most important part of the situation. It may not know that we already rejected an approach, that an old goal changed, or that a number came from an incomplete source. I also should not have to find and explain the same document every time.

The brain helps address that by giving knowledge a structure. Work history, skills, projects, evidence, feedback and decisions have their own homes. A routing guide tells the assistant where to look for a particular task. Search helps find the relevant record; the full record provides the support for the answer.

That last distinction matters. A search result is a clue. Before relying on it, the assistant needs the record behind it. A short result can leave out the date, qualification or reason that changes what the information means.

## How a useful piece of knowledge gets into the system

I do not want every message or meeting sentence to become a permanent fact. New information can arrive as a candidate. It keeps a connection to its source and remains available for review before becoming part of the trusted knowledge.

The review asks simple questions. Is this actually supported? Does it repeat something we already have? Does it conflict with a later decision? Does it contain information that should stay private? Is it a fact, a goal or an interpretation?

This helps stop a common failure: turning something I hope to achieve into something a resume later says I already achieved. The system needs to preserve the difference between a target, a reported result and a result backed by a specific document.

## A small example

Here is an invented example of the kind of record the system can keep:

> Decision: Use a plain-language weekly report with a short answer first.
>
> Reason: The team needs to see what changed and what to do next without reading a long analysis.
>
> Source: Reviewed reporting-format decision, September 8.
>
> Limit: This is a reporting preference. It does not authorize changing an account.
>
> Status: Reviewed. Revisit if the reporting audience changes.

That record can help with the next report, a new template or a briefing for an assistant. The assistant can use the preference while still checking the current account numbers. A decision about writing style is not a source for this week's revenue.

## The operating system behind how I work

Knowledge is only part of it. I also keep instructions for how to approach recurring work: retrieve the right context, use the right tool, write plainly, show gaps, prepare an exact change, get the needed approval and verify what happened.

For reporting, that means a clear answer, meaningful customer or revenue context, creative learning, risks and a next step. For project work, it means preserving the current state and other people's changes. For an account action, it means distinguishing a recommendation from an approved change and checking the result afterward.

These are reusable working habits. I am building them into a system so I do not have to remember to explain them in every session. The aim is continuity: a new assistant can pick up the work with enough context to be useful.

## How I use it with real tasks

For a creative brief, the system can help retrieve a past decision about the audience or approved message. The actual brief still needs current evidence and product information. For a project, it can help find the last accepted direction and the remaining work. For a career case, it can help find the source behind a result and keep the wording within what the source supports.

It also helps connect work across tools. A meeting can contain a decision. A project document can record its implementation. A later review can show whether the approach helped. Keeping the connections makes the next task easier to reason about than a pile of disconnected notes.

## My contribution

I decided what the system needed to remember, how the records should be organized and which rules should govern their use. I have worked with AI on retrieval, ingestion, consolidation and review. I keep revising the rules when I see an answer use the wrong source, miss a constraint or overstate a claim.

This is product work as much as knowledge work. The questions are about behavior: what should happen when two records disagree, when a source is old or when new information contains private details? A system that remembers everything but cannot handle those cases is not reliable enough for work.

## What this demonstrates

The brain demonstrates that I can build a repeatable way of working with AI, beyond asking individual questions. It combines knowledge organization, task design, privacy choices and quality review.

It does not mean the assistant knows everything I know, can replace my judgment or is automatically right. The value is that I can give it better context, trace the answer back to a source and keep improving the system when it gets something wrong.

The private records are not public portfolio material. The public record above is newly written with invented content. It shows the method without exposing the history behind it.
